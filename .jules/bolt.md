## 2026-06-23 - Logging Formatter Overhead
**Learning:** `JSON.stringify()` per request inside the `morgan` middleware and subsequent `JSON.parse()` within the `winston` formatter creates a significant serialization/deserialization bottleneck for request logs. Passing the structured object directly from `morgan` to `logger.http({...})` reduces overhead. Further, optimizing the `winston` format method to bypass unnecessary variable declarations and type checks when top-level fast-path properties (`info.method`, `info.url`) are detected provides an additional performance boost.
**Action:** When logging structured objects, always pass the object directly to the logger instead of stringifying it. Design custom formatters with a "fast path" that immediately reads top-level properties and returns, bypassing fallback parsing logic for the most common high-throughput logs.

## 2026-06-23 - Logging Formatter Overhead
**Learning:** `JSON.stringify()` per request inside the `morgan` middleware and subsequent `JSON.parse()` within the `winston` formatter creates a significant serialization/deserialization bottleneck for request logs. Passing the structured object directly from `morgan` to `logger.http({...})` allows Winston to merge the object properties directly into the top-level `info` object, bypassing nested object extraction.
**Action:** When logging structured objects, always pass the object directly to the logger instead of nesting it (e.g., `{ message: obj }` or stringifying it). Design custom formatters with a "fast path" that immediately reads top-level properties and returns, bypassing fallback parsing logic for the most common high-throughput logs.
